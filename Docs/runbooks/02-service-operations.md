# Operational Guide 02: Service Operations & Supervision

> **Topic:** Running, supervising, and managing background daemons, tmux sessions, and supervisor units.  
> **Source of Truth:** `src/host/tmux.ts`, `src/cli/start.ts`, `src/ingress/`, `router/src/lib.rs`.

---

## 1. Two-Tier Polyglot Architecture

AIBridge decouples ingress admission from task execution into two cooperating tiers:

```
Tailscale Request (POST /trigger)
               │
               ▼
   [Tier 1: aibr-router (Rust)]
   • Binds: tailscale0:8787
   • Checks constant-time Bearer auth
   • Validates payload size (1 MiB ceiling)
   • Atomic write to SQLite queue
               │
               ▼ Commit before 202 (SF-08)
     [ingress_outbox.db (WAL)]
               │
               ▼ Claim via lease
   [Tier 2: aibr worker (Bun)]
   • Sole semantic authorization authority
   • Enforces allowlists, policies, and charters
   • Communicates with loopback agent runtime
               │
               ▼ Loopback only (127.0.0.1:4096)
     [Local Agent Runtime]
```

### 1.1 Invariant SF-08: Commit Before 202
* The Tier 1 router responds with `HTTP 202 Accepted` **only after** durably committing the task to disk in `ingress_outbox.db` (`PRAGMA synchronous = FULL`).
* No uncommitted in-memory buffering exists. If disk persistence fails, the router returns `HTTP 503`.

## 2. Standard Service Management via Tmux

The default headless deployment utilizes tmux for process supervision.

### 2.1 Starting Services
Launch both the agent runtime and AIBridge daemon inside a dedicated session:

```bash
aibr start --profile dev-main
```

* Creates a background session named `aibridge-<profile>`.
* Allocates window 0 (`opencode`) running `opencode serve --port 4096 --hostname 127.0.0.1`.
* Allocates window 1 (`aibridge`) running the bridge server bound to your Tailscale IPv4 address.
* If already running, reports existing state without throwing an error.

### 2.2 Attaching & Monitoring
Attach to the interactive session:
```bash
tmux attach -t aibridge-dev-main
```

* Switch between windows: `Ctrl+B, 0` (OpenCode) and `Ctrl+B, 1` (Bridge).
* Detach safely: `Ctrl+B, D`.

### 2.3 Stopping Services
Gracefully terminate the session:
```bash
tmux kill-session -t aibridge-dev-main
```

## 3. Direct Daemon Execution

For custom process supervisors (Docker, Kubernetes, systemd system units), run components as direct foreground processes:

### 3.1 Initialize Tier 1 Ingress Queue
Before starting the router for the first time, provision the durable SQLite store:
```bash
aibr-router --init-store
```
*(Idempotent; creates schema in `~/.local/state/aibridge/<profile>/ingress_outbox.db`)*

### 3.2 Preflight Validation
Verify configuration, network binding, and database accessibility:
```bash
aibr-router --preflight
```

### 3.3 Running Tier 1 Ingress Router
```bash
aibr-router
```

### 3.4 Running Tier 2 Execution Worker
Starts the ingress drain loop without binding any external network listener:
```bash
aibr worker --profile dev-main
```

To expose the local Unix domain socket IPC bus for local management tools:
```bash
aibr worker --profile dev-main --ipc-publish
```

### 3.5 Running Legacy / Standalone Bridge Server
Runs Fastify bridge server directly (engine mode or shadow mode):
```bash
# Standard engine mode
aibr serve --profile dev-main

# Shadow mode (mirrors traffic to router for soak testing)
aibr serve --profile dev-main --shadow-mode
```

## 4. Platform Supervisors (launchd / systemd)

Supervisor units generated by `aibr setup` are written to user-level directories:

### 4.1 macOS (launchd)
Unit file: `~/Library/LaunchAgents/com.aibridge.<profile>.plist`

```bash
# Load and start daemon
launchctl load -w ~/Library/LaunchAgents/com.aibridge.dev-main.plist

# Unload daemon
launchctl unload -w ~/Library/LaunchAgents/com.aibridge.dev-main.plist
```

### 4.2 Linux (systemd User Service)
Unit file: `~/.config/systemd/user/aibridge-<profile>.service`

```bash
# Reload systemd configuration
systemctl --user daemon-reload

# Enable and start service
systemctl --user enable --now aibridge-dev-main.service

# Check service status
systemctl --user status aibridge-dev-main.service

# Stop service
systemctl --user stop aibridge-dev-main.service
```
