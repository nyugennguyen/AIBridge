# M7.3 progress: router skeleton and the four security gates

Branch `aibr-v2`. Base commit `80f40b1` (M7.2). This report covers M7.3 only; M7.2's
work is not restated.

## What landed

`aibr-router` grew from a compile-able crate carrying the generated contract types into
a serving process: four stateless routes, the structural gate in front of them, and the
ADR 0008 §8 layer-1 preflight that decides whether this process may hold a socket.

```
router/src/
  lib.rs       modules, and the Tier-1/Tier-2 boundary in the crate docs
  contracts.rs GENERATED — unchanged by this task
  config.rs    BridgeConfig loading; canonicalised project roots
  auth.rs      constant-time bearer, opaque Debug
  validate.rs  the structural gate: charset, envelope, realpath containment, body cap
  routes.rs    the four routes, the fallback, the minted job id
  error.rs     four refusals, one body shape, nothing echoed
  bind.rs      §8 layer 1 preflight and EX_CONFIG
  main.rs      load -> preflight -> bind -> serve
```

### Dependencies added

Four, all pinned with `=`, all `default-features = false` with an explicit list and a
per-choice justification in `router/Cargo.toml`:

| Crate | Version | Why this one |
| --- | --- | --- |
| `axum` | `=0.8.9` | M7.1 spike version, for comparability. **`ws` feature excluded**, so a `101` is not constructible in this build |
| `tokio` | `=1.53.1` | M7.1 spike version. `rt-multi-thread` to keep the 9-thread measurement comparable; `net`, `macros`, `signal` |
| `subtle` | `=2.6.1` | constant-time equality; pure Rust, so M7.9's `cargo zigbuild` musl matrix has no C toolchain to satisfy |
| `if-addrs` | `=0.15.0` | interface enumeration for the preflight, which must answer without binding |
| `getrandom` | `=0.4.3` | OS CSPRNG for minted admission correlation tokens |

`tower = "=0.5.3"` is a **dev-dependency only** — `Router::oneshot`, so no test in
`router/tests/` opens a socket.

### Routes, and what each returns

| Method | Path | Status | Body |
| --- | --- | --- | --- |
| `GET` | `/health` | `200` | `{ok: true, schemaVersion: "v1"}` |
| `POST` | `/trigger` | `202` | `{accepted: true, job_id, status_url, schemaVersion}` |
| `GET` | `/jobs/{id}` | `404` | `{error: "not found", schemaVersion}` — **for every id** |
| `POST` | `/report` | `202` | `{accepted: true, schemaVersion}` |

Every route is behind the bearer, reads included. Every response — refusals included —
carries `schemaVersion`. Refusals are `401` / `400` / `404` / `413`, all with the same
two-field body. **There is no `403` anywhere in this crate**, because "you are
forbidden" is a Tier 2 sentence.

`GET /health` does **not** call opencode. The engine's route returns
`{ok: true, opencode: await health()}`, which makes a liveness probe depend on a second
process; from M7.7 the engine sits behind this router, so that would tell a supervisor
to restart the wrong process. See "Deviations" below.

## The four findings

Each is closed with the reproduction from
[`Docs/security/milestone-0-threat-model.md:100`](../security/milestone-0-threat-model.md),
not a paraphrase of it.

| ID | Closure | Test |
| --- | --- | --- |
| `F-01` | `job_id` restricted to `[A-Za-z0-9_-]{1,128}` on trigger, report and the read route | `f01_a_traversal_job_id_is_refused_on_trigger`, `f01_a_traversal_job_id_is_refused_on_report`, `f01_a_traversal_job_id_in_a_path_is_never_a_job`, `validate::tests::f01_the_threat_model_reproduction_is_refused` |
| `F-03` | bearer on **every** route, reads included | `f03_the_job_read_route_refuses_an_unauthenticated_request`, `f03_no_route_answers_without_a_bearer`, `f03_the_unauthenticated_refusal_carries_www_authenticate` |
| `F-04` | `std::fs::canonicalize` (realpath) then component-wise containment | `f04_a_symlink_escaping_the_configured_root_is_refused`, `f04_a_real_subdirectory_of_the_configured_root_is_admitted`, `f04_every_containment_failure_produces_one_indistinguishable_answer` |
| `F-06` | required `schemaVersion` envelope, unknown **or missing** refused, never coerced | `f06_an_unknown_schema_version_is_refused`, `f06_a_missing_schema_version_is_refused`, `f06_the_version_gate_covers_report_as_well`, `validate::tests::f06_*` |

`F-02` is **not** in scope: it is `MESH`-side egress credential binding, closed at
enqueue by M7.8's `egress_outbox` (ADR 0008 §2.6).

Two `F-04` details worth naming. The escape test uses a symlink *inside* a configured
project root pointing at a sibling, because that is the case where the engine's lexical
`resolve()` comparison **succeeds** — a plain `..` would be caught by the engine too.
And the sibling-prefix case (`<root>-evil`) is asserted separately, because
`Path::starts_with` compares whole components while a hand-rolled
`starts_with(root.to_string_lossy())` would admit it.

## The Tier-1 / Tier-2 boundary — what was deliberately not implemented

The router **never** calls or approximates `assertSourceAuthorized`, never decides
allowlist membership, never reads `plan_status` as a trust signal, and never reads
project contents or a job store. Each omission is asserted from the outside:

| Not implemented | Test that fails if it is added |
| --- | --- |
| source allowlist | `a_structurally_valid_trigger_from_an_unauthorized_source_is_still_admitted` |
| source allowlist (report) | `a_report_from_an_unauthorized_source_is_still_admitted` |
| plan approval | `plan_status_approved_is_not_a_trust_signal_to_the_router` |

The support fixture configures exactly one allowed source,
`the-only-authorized-source`, and every request under test claims to be from
`some-source-that-is-not-configured`. A test asserts those differ, so the boundary tests
cannot pass for the wrong reason.

`canonical_project_dir` is the one judgement call, and it is narrower than
`assertProjectAllowed` on purpose: it asks whether a path escapes *every* configured
root through a symlink, not whether the caller may use the project. It fails
identically for every reason — non-absolute, nonexistent, escaping, outside every root,
sibling prefix — and `f04_every_containment_failure_produces_one_indistinguishable_answer`
asserts the five responses are byte-identical, so it is not an allowlist oracle. The
worker repeats the check at the effect boundary in M7.7.

## Deviations from the brief, and why

1. **`GET /jobs/{id}` returns `404`, never a `200`.** The brief said to document that
   the router does not read the job store; it is the router's only correct answer, not a
   stub. This process genuinely does not know whether the job exists. M7.7 wires the
   route to the worker's view.
2. **The router's `202` omits `target_agent_id`, `status` and `opencode_session_id`**,
   all three of which are in the committed `triggerResponseSchema`. Each describes a
   routing decision, a job lifecycle, or a runtime this process does not have.
   Emitting `accepted` would claim an observable state; echoing a caller-supplied
   `target_agent_id` would assert that this process *is* that target. **M7.7 must
   reconcile the response against the committed schema before cutover.**
3. **`GET /health` drops the `opencode` field** the engine returns. Deliberate; see above.
4. **`schemaVersion` is an envelope key alongside the payload, not a field inside it.**
   `trigger-request.schema.json` has no such field and its generated type is
   `deny_unknown_fields`, and `contracts/v1/` and `src/` are both out of bounds for this
   task. The key is *required*, checked, and then removed; every other unknown key still
   reaches `deny_unknown_fields`.
5. **A malformed `job_id` in a URL is a `404`, not a `400`.** The route has no store, so
   it has no truthful `400` about an id it cannot resolve. The `F-01` reproduction is
   additionally asserted against `valid_job_id` directly, so the gate is tested as well
   as the route.
6. **A configured project root that does not resolve is dropped, not a startup failure.**
   Provably equivalent (no path canonicalises *through* a root that does not canonicalise
   itself), and refusing to start would couple availability to configuration a host may
   never use.

## Known gaps, honestly

- **No SQLite, no durable write, no queue.** M7.5. The `202` is therefore a *lie the
  worker will eventually make true*: the `job_id` is an admission correlation token, not
  a reference to a durable record, and `status_url` is a string, not a link to anything
  this process can serve.
- **§8 layer 1 is half-implemented.** The address-presence half is here. The
  `tailscale0` interface-name half is **M7.11** and deliberately absent: this host has
  no `tailscale0`, so enforcing it would make the router unstartable and untestable
  here. `bind::TAILSCALE_INTERFACE` and `bind::interface_names` exist so M7.11 wires one
  string rather than rediscovering the dependency. Layers 2–4 (`nft`, `IPAddressAllow`,
  ACL) are also M7.11.
- **ADR 0008 §9's "byte-identical `400` bodies across languages"** is not satisfied for
  the ingress routes. The router's bodies are
  `{error: <static string>, schemaVersion}` and Zod strips unknown keys, so the two sides
  are not byte-identical. M7.2's parity corpus covers the 15 orchestration fixtures; the
  ingress-route parity is unreconciled and belongs with the M7.7 cutover.
- **M7.4's `bridge.ingress_mode` will not start this binary** until `contracts/` is
  regenerated. `BridgeConfig` is `deny_unknown_fields`, so a new config key is a contract
  change. This is the correct direction — the schema is the source of truth — but it is
  a coupling M7.4 has to know about. `the_committed_example_config_parses` is the test
  that will fail.
- **A single idle RSS sample is not the ADR 0008 §9 resource gate.** Measured on the
  reference host: release binary **689 KiB**; running idle, **2144 KiB RSS across 9
  threads** (a second run measured 2128 KiB — the same small plateau-to-plateau variation
  ADR 0008 §1 records for Bun, and the reason this is reported as an observation). The
  9 threads match M7.1's stub, so the multi-threaded runtime kept the measurement
  comparable. All of it is inside §9's ≤ 4 MiB figure against the 1.91 MiB stub lower
  bound, but this is one idle capture, not the ≥ 60 s median/p95 under sustained load
  §5.1.1 requires, so it is **not gateable evidence**.
- **No end-to-end integration with the engine.** The engine still listens; M7.7 removes
  it.

## Two defects this corpus found while being written

Both are fixed; both are recorded because the next writer should know that a router can
compile and be wrong in exactly these ways.

1. **`GET /health` answered without a bearer.** The first draft took no `State` and no
   `HeaderMap`. `f03_no_route_answers_without_a_bearer` failed on it immediately. This is
   the same shape as `F-03` — a read route quietly outside the boundary — which is the
   argument for writing the all-routes table rather than four per-route tests.
2. **`bind_address()` produced `:::8787` for an IPv6 `bridge.host`.** `format!("{}:{}",
   host, port)` is not a socket address for v6. Fixed by bracketing; asserted by
   `an_ipv6_bind_host_is_bracketed`.

## Behaviour over a real socket

Not part of the gate list, recorded because the gate list drives `oneshot` and a socket
is where a header or a body-cap behaves differently:

```
health with a bearer                 -> 200
health with no bearer                -> 401
POST /trigger, project_dir="/tmp"    -> 400 {"error":"project_dir is not a path inside
                                         this deployment's project roots",...}
GET /v1/mesh/terminal, Upgrade: ws   -> 404
```

The `400` is the containment gate running for real: that measurement config declares
`projects: []`, so there is no root to be inside.
