# AIBridge 3.2.0

> **Draft text for the GitHub Release.** Full details: [CHANGELOG, 3.2.0](../../CHANGELOG.md#320---2026-11-26).

Adds a job API and job CLI, reconciles jobs and cleans up orphaned processes after a bridge restart, hardens security (plan self-approval fix, job read and id hardening, wider secret redaction), and removes about 45k lines of unwired code. The wire format of `/trigger` and `/report` does not change, apart from the new job id validation.

## BREAKING

Three items that were deprecated in 3.1.1 and have done nothing since then are removed. They were no-ops, announced one release ahead (ADR 0014), so this ships as a minor release.

- **`aibr tui`** is now an unknown command (nonzero exit). Use Claude Code with the AIBridge plugin; on the worker use `aibr jobs pending`, `aibr approve`, `aibr logs -f`.
- **`aibr worker --ipc-publish`** is now rejected as an unknown flag, so a hand-written service unit that still passes it will not start. Delete the flag from the unit; units generated from 3.1.1 onward do not have it.
- **Config `terminal` (`terminal.backend`)** is gone from the schema. A profile that still has the key keeps loading and logs one warning. Delete the key; nothing else to do.

Also removed, with no user-facing effect because `aibr serve` never used them: the orchestration kernel and `POST /orchestration/commands` and `POST /orchestration/capability-preview` (BREAKING (unused)), `src/rules`, the dead part of `src/mesh`, and several unwired leaf modules.

## Upgrade notes

- `GET /jobs/:id` needs credentials: 401 without the bearer, even on `request_signing: "off"` nodes. On `optional` and `required` nodes a signed peer sees only the jobs it requested; on `off` nodes the bearer alone reads any job.
- `job_id` must match `^[A-Za-z0-9][A-Za-z0-9_-]{0,127}$` (400 otherwise). In-flight work with a caller-chosen id outside the pattern fails after the upgrade. A case-only duplicate id gets 409 on every platform.
- One `aibr serve` or `aibr worker` per profile (lock file); a second one exits with an error.
- A graceful stop ends running Claude Code jobs as `interrupted: bridge stopped`; a restart ends jobs that may have started as `interrupted: bridge restarted`. Neither is retried automatically.
- The new job routes and MCP tools (`bridge_events`, `bridge_cancel`) need signed requests. On `request_signing: "off"` nodes only the operator can use them.
- OpenCode jobs that need approval wait for `aibr approve` instead of being refused.

## Highlights

- **Job API and CLI.** `GET /jobs`, `GET /jobs/:id/events`, `POST /jobs/:id/cancel`; `aibr jobs`, `aibr job`, `aibr cancel`, `aibr attach`; MCP `bridge_cancel` now works and `bridge_events` is new.
- **Restart reconcile and orphan cleanup.** Jobs left behind by a restart are reconciled, runtime processes left by a killed bridge are terminated at the next start, and job deadlines are swept every 60 seconds.
- **Security.** A caller can no longer approve its own plan on the OpenCode runtime; `GET /jobs/:id` is no longer anonymous; job ids can no longer write outside the jobs directory; outbound reports time out after 15 s.
- **Secret redaction.** Job results (summaries, errors, stderr and script tails, `/report`) are scrubbed for many more kinds of secret.
- **Slimmer tree.** About 45k lines of unwired code are gone, and `bun run docs:reachability` keeps it from growing back (ADR 0015, ADR 0016).
