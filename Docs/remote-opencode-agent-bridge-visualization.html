AIBridge system design

Remote Opencode Agent Bridge → Multi-Agent Mesh

AIBridge lets opencode agents running on different machines call each other over a private Tailscale network. The POC starts with a development machine triggering a testing VPS agent; the architecture keeps registry, routing, job lifecycle, and auth boundaries ready for a future N-machine mesh.

POC: 2 machines Future: N-machine mesh Node.js / TypeScript HTTP webhooks Tailscale-only tmux + opencode serve Plan Annotator approval

Job Flow

Development completes deploy

dev-main decides that testing/QA is needed on the VPS.

Review plan when needed

Plan Annotator presents generated implementation plans for approval before remote dispatch.

Trigger remote agent

dev-main sends approved POST /trigger to test-vps over Tailscale.

Validate and accept job

test-vps checks auth, schema, plan metadata, capability, project directory allowlist, and opencode health.

Create opencode session

AIBridge uses the opencode SDK/API to create a new session and send the prompt asynchronously.

Monitor execution

The bridge watches SSE/session status, with polling fallback if the event stream disconnects.

Send report callback

test-vps posts a structured report to dev-main with findings, artifacts, and status.

Core Components

Bridge HTTP ServerOwns /trigger, /report, /health, /jobs/:id endpoints.
Opencode AdapterCreates sessions, sends prompts, monitors status through SDK/API.
Job Lifecycle ManagerTracks received → running → reporting → completed/failed.
Agent RegistryStatic config in POC; dynamic discovery later.
Callback ReporterRetries report delivery and persists failed callbacks.
Security LayerTailscale ACLs, bearer/HMAC auth, project-dir allowlists.
Plan AnnotatorApproval gate for generated plans before dispatching sensitive or multi-agent work.

Message Contracts

Trigger request source_agent_id, target_agent_id, capability, project_dir, prompt, callback_url, timeout_seconds, metadata including plan_status and plan_reference.
Report callback job_id, opencode_session_id, status, summary, findings, artifacts, timestamps.

Security and Failure Guardrails

AreaDesign rule
NetworkTailscale-only access; no public internet exposure for POC.
AuthWebhook bearer token first, HMAC/mTLS-ready interface later; opencode uses OPENCODE_SERVER_PASSWORD.
FilesystemRemote project_dir must be allowlisted on the target machine.
Plan approvalSensitive jobs require approved Plan Annotator metadata before remote dispatch.
TimeoutsEvery job has max duration; timeout aborts or marks session failed.
SSE instabilityReconnect with backoff; fallback to polling session status.
Callback failureRetry, then persist report locally for later inspection.

POC Scope

Include TypeScript bridge, two-machine config, /trigger, /report, Plan Annotator approval step, opencode SDK/API, new session per trigger, monitoring, callbacks, tmux run docs, tests, structured logs.
Exclude Public internet exposure, full dynamic discovery, dashboard, non-opencode providers, Kubernetes, queue infrastructure, browser UI.
